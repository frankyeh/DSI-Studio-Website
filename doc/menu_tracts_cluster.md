# [Tracts Cluster] Menu

The **[Tracts Cluster]** menu in the Fiber Tracking window organizes loaded tract bundles in the Tracts list, batch-assigns or exports bundle-level display colors and scalar values, splits a selected tract bundle using external per-streamline integer labels, and partitions a tract bundle into sub-bundles using unsupervised geometric clustering (**Single-Linkage**, **K-means**, or **EM**). For loading or saving multi-bundle tract files (`.tt.gz`, `.trk`, `.trx`) and managing bundle visibility, see the [Tracts menu](/doc/menu_tracts.html); for atlas-based bundle recognition, automated bundle renaming, atlas-guided clustering, and per-streamline color or value files, see the [Tracts Misc menu](/doc/menu_tracts_misc.html); for interactive streamline trimming and ROI filtering, see the [Tract Edit menu](/doc/menu_edit.html).

## Names and sorting

| Menu item | Behavior |
|---|---|
| **Open Tracts Name...** | Opens a file dialog (`*.txt`, defaulting to `<stem>_name.txt`) and reads whitespace-separated bundle names, applying them from the **bottom** of the Tracts list upward (`last row` paired with `last token`, renaming up to `min(row count, name count)` rows and updating each bundle's stored name). Pairing from the bottom allows a `K`-entry label list to rename `K` newly created or recently opened cluster bundles at the end of the Tracts list without overwriting earlier bundles above them (or renames every row top-to-bottom when `K` equals the total row count). Because tokens are split on any whitespace (spaces, tabs, or newlines), write multi-word bundle names with underscores rather than spaces (for example, `Arcuate_Fasciculus_L`), matching the companion `<tract_file>.txt` label format used by multi-cluster `.tt.gz` and `.trk` files. |
| **Sort Tracts by Name** | Reorders all bundle rows in the Tracts list in ascending lexicographical (`ASCII`/`UTF-8`) order by **Name** while preserving each bundle's visibility checkbox state, visible/deleted/seed counts, streamline geometry, and 3D rendering buffers (updating the list and 3D render order without recomputing 2D slice overlays). Because sorting is lexicographical rather than numeric, default cluster names sort as `cluster0`, `cluster1`, `cluster10`, `cluster2`, ... unless zero-padded or renamed first. |

## Cluster colors

| Menu item | Behavior |
|---|---|
| **Color All Clusters** | Assigns a distinct, deterministic RGB color (`index`-based palette) uniformly across all streamlines of **every** tract bundle currently in the Tracts list (both checked and unchecked rows), and switches **Tract Color › Style** in the Rendering options panel from directional coloring to **Assigned**. |
| **Select Color to Current Cluster...** | Opens a color picker dialog initialized to the **currently selected** (highlighted) bundle's first streamline color, applies the chosen uniform RGB color across all streamlines in that single bundle, and switches **Tract Color › Style** in the Rendering options panel to **Assigned**. Requires an active row selection in the Tracts list; although the color picker shows an alpha control, per-bundle colors store RGB channels while overall streamline transparency is controlled via **Tract Color › Opacity** in the Rendering options panel. |

## Cluster files

Cluster file operations act on **bundle-level** colors and scalars across **checked** rows in the Tracts list, except **Open Cluster Labels...**, which splits the single **currently selected** bundle using one integer cluster ID per visible streamline. (To load or save per-streamline RGB colors or per-streamline scalar values within a single bundle, use **[Tracts Misc][Open Tract Colors...]** and **[Tracts Misc][Open Tract Values...]** instead.)

| Menu item | Behavior |
|---|---|
| **Open Cluster Colors...** | Opens a plain-text file (`*.txt`, defaulting to `<stem>_color.txt`) containing whitespace-separated integer RGB triplets (`R G B`, `0–255` per channel, typically one triplet per line), assigns each consecutive triplet as a uniform RGB color to the next **checked** bundle in Tracts-list order (skipping unchecked rows), and switches **Tract Color › Style** to **Assigned**. |
| **Open Cluster Labels...** | Splits the **currently selected** (highlighted) tract bundle according to a plain-text file (`*.txt`, defaulting to `<bundle_name>_label.txt`) of whitespace-separated non-negative integer cluster IDs (`0`, `1`, `2`, ...), reading one integer per visible streamline in streamline order (if fewer integers are provided than visible streamlines, remaining streamlines receive label `0`; extra integers beyond the visible streamline count are ignored). **Deletes and replaces** the selected bundle row with new checked bundle rows named `cluster0`, `cluster1`, ... for every non-empty label ID from `0` through the maximum label value (preserving source geometry, voxel size, MNI transformation, and tracking report), then automatically applies **Tracts Cluster › Color All Clusters** (**Assigned** coloring). Duplicate the bundle first with **Tracts › Copy Tracts** if you want to retain the unsplit bundle, because replacing the row cannot be undone with **Tract Edit › Undo**. |
| **Open Cluster Values...** | Opens a plain-text file (`*.txt`, defaulting to `<stem>_values.txt`) of whitespace-separated floating-point numbers — one scalar value per **checked** bundle (such as bundle-level t-statistics, p-values, or effect sizes) — stores each scalar on the corresponding checked bundle, and switches **Tract Color › Style** to **Loaded Value**. The number of values in the file must **exactly equal** the number of currently checked bundles in the Tracts list, or loading aborts with a count-mismatch error. Rendered colors map each bundle's scalar through the active tract colormap between **Tract Color › Min Value** (default `0.0`) and **Tract Color › Max Value** (default `1.0`) in the Rendering options panel, so adjust **Min Value** and **Max Value** whenever your scalars fall outside `0–1`. If a bundle already carries per-streamline loaded values (for example from a `.trx` file or **Tracts Misc › Open Tract Values...**), per-streamline values take precedence during rendering. |
| **Save Cluster Colors...** | Writes the assigned RGB color of every **checked** bundle in the Tracts list to a plain-text file (`*.txt`, defaulting to `<stem>_color.txt`), outputting one space-separated `R G B` integer line (`0–255` per channel, taken from each bundle's first visible streamline, or `0 0 0` if a checked bundle has zero visible streamlines) per checked row in top-to-bottom list order. Unchecked bundles are omitted. |

## Clustering

All three unsupervised clustering methods operate on the **currently selected** (highlighted) tract bundle in the Tracts list. Executing any clustering method **deletes the original bundle row** and replaces it in-place with newly created checked sub-bundles (`cluster0`, `cluster1`, ...) sorted from **largest to smallest** visible streamline count, followed by automatic distinct palette assignment (**[Tracts Cluster][Color All Clusters]**, setting **Tract Color › Style** to **Assigned**). Because replacing the source row is not undoable via **[Tract Edit][Undo]**, use **[Tracts][Copy Tracts]** beforehand when comparing clustering methods or parameter settings.

| Menu item | Behavior |
|---|---|
| **Single-Linkage Clustering** | Groups streamlines in the **currently selected** bundle via graph-based single-linkage (connected-component) geometric proximity. Prompts first for the **maximum number of groups** (`1–5000`, default `50`) and second for **clustering detail** (`0.20–50.00`, labeled `clustering detail (mm):` and defaulting to the dataset's X voxel size). **Unit caution:** Although the prompt label specifies `mm`, the clustering algorithm applies this numeric threshold directly in **voxel coordinates**: streamline midpoints are quantized onto a coarse grid of step `detail` voxels (`26`-connected neighborhood search), and two streamlines merge into the same cluster when both canonicalized (coordinate-sorted) endpoint distances are `<= detail` voxels and their voxel-space streamline lengths differ by `<= 2 × detail` voxels. On non-`1 mm` datasets, divide your desired millimeter tolerance by the voxel size (smaller values isolate tighter fascicles; larger values merge broader pathways). Keeps up to the top `N` largest multi-streamline clusters as checked rows (`cluster0`, `cluster1`, ...) and collects isolated singletons plus smaller overflow clusters into a trailing **`others`** row whose streamlines are marked **deleted** (`0` visible streamlines in 3D; select `others` and choose **Tract Edit › Undo** or **Tracts › Separate Deleted Tracts** to inspect them). *(Note: if every streamline merges into `<= N` multi-streamline clusters with zero residual streamlines, the smallest kept cluster row at the end of the list is still converted into the hidden `others` row.)* |
| **K-means Clustering** | Partitions all streamlines in the **currently selected** bundle using k-means clustering in a 10-dimensional **voxel-coordinate** feature space: start endpoint `(x1, y1, z1)`, end endpoint `(x2, y2, z2)`, midpoint `(xm, ym, zm)`, and scaled vertex count (`floor(1.5 × point_count)` rounded down to a multiple of `3`). Prompts only for the **maximum number of groups** (`1–5000`, default `50`; internal cluster assignments use an 8-bit unsigned index `0–255`, capping effective output at **at most `256` non-empty clusters**). Unlike **Single-Linkage Clustering**, start and end coordinates are **not** canonicalized by spatial order, so streamlines stored with reversed traversal direction occupy distinct regions of feature space. Replaces the selected bundle with checked `cluster0`, `cluster1`, ... rows sorted largest-first (assigning every streamline to a cluster with no `others` row) and applies **Tracts Cluster › Color All Clusters**. |
| **EM Clustering** | Partitions all streamlines in the **currently selected** bundle using Expectation-Maximization (Gaussian mixture model) clustering over the same 10-dimensional **voxel-coordinate** feature vector used by **K-means Clustering** (start endpoint, end endpoint, midpoint, and scaled vertex count, without endpoint-order canonicalization). Prompts only for the **maximum number of groups** (`1–5000`, default `50`; capped internally at **at most `256` non-empty clusters** via 8-bit unsigned cluster indices). Replaces the selected bundle with checked `cluster0`, `cluster1`, ... rows sorted from largest to smallest streamline count (with no `others` row) and applies **Tracts Cluster › Color All Clusters**. |

## Atlas recognition and bundle workflows

- **Unsupervised clustering vs. atlas-based recognition:** **[Tracts Cluster]** groups streamlines purely by trajectory geometry without anatomical priors, naming output rows `cluster0`, `cluster1`, .... To classify, filter, or split streamlines against DSI Studio's population tractography atlas, use **[Tracts Misc][Recognize...]** (overlap report for the selected bundle), **[Tracts Misc][Recognize and Rename]** (renames each checked bundle to its closest-matching atlas pathway), or **[Tracts Misc][Recognize and Cluster]** (splits the selected bundle into anatomically named atlas bundles while discarding unrecognized streamlines); see the [Tracts Misc menu](/doc/menu_tracts_misc.html). After **[Tracts Misc][Recognize and Rename]** assigns anatomical names to clustered sub-bundles, **[Tracts Misc][Merge Tracts by Name]** can consolidate duplicate labels and **[Tracts Cluster][Sort Tracts by Name]** orders the resulting list alphabetically.
- **ROI filtering and saving clustered bundles:** To filter existing cluster rows by anatomical inclusion or exclusion masks (`ROI`, `ROA`, `End`), configure regions in the Region list and apply **[Tracts][Filter Tracks by ROI/ROA/End]** (or trim interactively from **[Tract Edit]**). Choosing **[Tracts][Save All Tracts As ...]** exports all **checked** cluster rows into a single `.tt.gz` or `.trk`/`.trk.gz` file while preserving cluster IDs (and reading or pairing companion `<file>.txt` bundle names when reopened via **[Tracts][Open Tracts...]**), whereas **[Tracts][Save All Tracts As Multiple Files...]** writes one tract file per checked cluster into a folder using each row's **Name**.
